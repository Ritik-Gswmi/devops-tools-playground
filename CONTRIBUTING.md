# Contributing

Contributions that make the DevOps workflow clearer and easier to practice are welcome.

## Documentation changes

- Keep each chapter focused on one stage of the workflow.
- Explain what a tool does, why it is used, and how it connects to the sample workflow.
- Include commands only when they are safe to run and label the directory or repository they expect.
- Show expected results and common failure causes where useful.
- Link to the source of truth elsewhere in this repository instead of duplicating its implementation. Keep the handbook usable without relying on another project repository.
- Never include real secrets, personal data, or credentials in examples.

## Pull requests

Keep changes focused. In the pull request description, summarize the learning goal and list the commands or links you checked. If an example changes, update its guide and the handbook chapter that points to it.
